02 · Architecture

전체 아키텍처

02 · Architecture — ① DB
Prisma(ORM)가 객체↔SQL을 번역해 NestJS와 DB를 잇고, pgvector로 벡터까지 한 DB에 저장·검색
02 · Architecture — ② AI
임베딩 모델 + 멀티모달 LLM(이미지 평가·게시판 관리), 이미지 임베딩은 로컬 CLIP으로 내부 처리
02 · Architecture — ③ MCP
MCP 서버를 거쳐 표준 규약(JSON-RPC)으로 외부 도구 연동 → Tavily 검색, 확장 가능한 구조

04 · 주요 기능 ①

이미지 유사도 측정 · 평가

RAG · 임베딩 + pgvector
  • 사전: 미술관 공개 API 100개 → 로컬 CLIP 임베딩 → pgvector 저장
  • 검색: 입력 이미지 임베딩 → 코사인 유사도로 후보 5개
  • 판별: 5개 후보를 Vision LLM이 비교 → 최종 1개 선정·평가
  • 핵심: 로컬 CLIP(빠른 후보) + Vision LLM(정확한 판별) 2단계
04 · 주요 기능 ②

MCP 연결 외부 검색

MCP · JSON-RPC + 외부 연동
  • NestJS가 MCP 서버를 별도 프로세스로 실행 (JSON-RPC / stdio)
  • MCP 서버가 HTTPS로 Tavily를 호출해 작품 정보 검색
도구가 늘어나면 MCP 서버를 상주시켜 재사용하고, 여러 도구를 같은 표준 규약으로 연동·확장할 수 있는 구조입니다.
04 · 주요 기능 ③

Auto-Mod Agent

Agent · 자율 도구 선택 + 무한루프 방지
  • rule_check 먼저 → 치명적 위반이면 즉시 차단
  • 아니면 LLM이 도구를 자율 선택(문맥·이력·LLM 판단)하는 추론 루프
  • 욕설=차단 / 맥락적 부정=경고 까지 잡아냄
  • 안전장치: max_loop 제한 + LLM 실패 시 규칙 기반 폴백
05 · Retrospective

회고 · 개선 방향

이미지 검색 정확도로컬 CLIP(가벼운 모델)이라 1차 검색이 부정확 → 후보 5개를 LLM에 의존
→

MCP 서버 생성 비용외부검색 요청마다 프로세스를 새로 생성
→
